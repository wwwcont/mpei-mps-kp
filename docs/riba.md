# Пошагово с нуля

## Устройство на пальцах

Ты проектируешь маленький пульт: человек жмёт цифру, внешняя железка присылает числа, пульт их складывает и отдаёт результат наружу.

Термины, без которых дальше не прочитать:

- **МК AT89S53** — микроконтроллер семейства 8051: процессор, 256 байт ОЗУ, память программ, таймеры, 2 внешних прерывания, 4 порта по 8 ножек.
- **Шина** — общие провода, по которым МК обращается к внешним микросхемам: P0 (младший байт адреса, затем данные), P2 (старший байт адреса), P3.6 = WR, P3.7 = RD, ALE.
- **Адрес** — 16-битное число, которое МК выставляет на шину командой `movx`. Старшие три бита адреса (A15…A13) выбирают устройство.
- **Дешифратор 74HC138** — превращает три бита A15…A13 в один из восьми сигналов Y0…Y7 (активен нулём). Каждый выход — **CS** (Chip Select) своего устройства; номер выхода задан в табл. 1 ТЗ. Дешифратор работает, только пока **CS_EN = P3.4 = 1** (вход E2).
- **RD / WR** — стробы чтения/записи МК. `movx A,@DPTR` даёт импульс RD, `movx @DPTR,A` — импульс WR.
- **Регистр-защёлка (573)** — 8 триггеров: запоминает байт с шины и держит его на выходах, пока не запишут новый.
- **Регистр 173** — то же, но 4 бита; держит состояние столбцов клавиатуры.
- **Буфер с тремя состояниями (244)** — выдаёт свои входы на шину только когда его выбрали, в остальное время его выходы отключены.
- **Двухпортовое ОЗУ IDT7005** — память 8 Кбайт с двумя независимыми наборами адреса/данных/управления: левый порт целиком у МК (читает и пишет), правый целиком у внешнего устройства на отдельном разъёме: адрес, данные и строб записи — оно пишет отсчёт X2 само, независимо от МК.
- **Прерывание INT0/INT1** — спад на ножке P3.2/P3.3 заставляет МК выполнить обработчик по фиксированному адресу (03h / 13h).
- **Таймер** — 16-битный счётчик машинных циклов (1 мкс при 12 МГц); при переполнении вызывает прерывание (0Bh / 1Bh).

Что подключено к МК:

| Устройство | Зачем | Как с ним говорят |
| --- | --- | --- |
| Клавиатура 12 кнопок | человек вводит цифру X1, «Тест», «Сброс» | пишем столбцы в регистр, читаем строки через повторитель; нажатие → INT0 |
| Индикатор, 1 цифра | показать нажатую цифру или ошибку | пишем код сегментов в регистр |
| Кольцевой буфер (IDT7005) | копить числа X2 от внешнего устройства | оно пишет в свой порт и дёргает INT1; МК читает по одному |
| Регистр Y2 | выдать результат наружу | пишем Y2, дёргаем строб на P1 |
| Ножка Y1 на P1 | строб по кнопке «Тест» | 0 на время T1, потом 1 |

Весь смысл работы в одну строку: **Y2 = (G + M + X1 + X2) mod 256**, пока X1 ≠ 0 и в буфере есть X2 (G — номер группы: 6, 7, 8, 9, 12, 17, 21).

## Шаг 2. Раздать ресурсы МК (30 минут)

Таблица «ножка/таймер/адрес → кому» — это и раздел функциональной схемы в ПЗ1, и раздел 3.2 в ПЗ2 (ПЗ2 генератор заполняет сам).

1. Ножки МК:
   - P0 — младшие 8 бит адреса, потом данные (мультиплексированы, адрес защёлкивается по ALE);
   - P2.0–P2.4 — A8–A12 (буфер до 2100 байт требует 13 адресных линий A0–A12 у IDT7005);
   - P2.5–P2.7 — A13–A15 → входы A0–A2 дешифратора;
   - P3.4 — CS_EN (E2 дешифратора), Ē0 = Ē1 = GND;
   - P3.2 / P3.3 — INT0 (клавиатура) / INT1 (строб X2);
   - P3.6 / P3.7 — WR / RD; P1.k, P1.(k+1) — стробы Y1, Y2.
2. Адреса: окно устройства — n·2000h … n·2000h + 1FFFh (n — номер выхода Yn). Пример: Y5 → 0A000h–0BFFFh.
3. Карта памяти: окна по 8 Кбайт, свободные выходы дешифратора (у примера Y0, Y2, Y3, Y4) — «не используется».
4. Таймеры: Y1 и T3 — Timer0 (задачи не пересекаются: во время «Теста» индикатор погашен), Y2 — Timer1.
5. Приоритеты: ввод X2 (INT1) — высокий (ТЗ: «с максимально возможным приоритетом»), остальные — низкий.
6. Внутренняя память: «голова» и «хвост» — по заданным адресам (по 2 байта), флаги — по заданным битам, остальные переменные — от 30h.

Проверка себя: ни одна ножка, адрес или байт ОЗУ не встречается в таблице дважды.

Твоя задача — **понимать** каждый узел: пройди по листу и для каждой микросхемы ответь, куда подключены питание, CS, RD/WR и данные.

Что должно быть на листе (проверь глазами):

1. МК, кварц 12 МГц с двумя конденсаторами, RC-сброс (10 мкФ + 10 кОм).
2. Защёлка младшего байта адреса (573) по ALE.
3. Дешифратор 74HC138: A0/A1/A2 ← A13/A14/A15, E2 ← CS_EN (P3.4), Ē0/Ē1 → GND.
4. IDT7005 (slave: M/S → GND, BUSY → +5 В): левый порт — МК (A0–A12, D0–D7, CE ← CS_buf, OE ← RD, R/W ← WR);
   правый — разъём доступа к буферу (A0R–A12R, I/O0R–I/O7R, R/W ← строб X2, CE → GND, OE → +5 В); строб X2 → INT1.
5. Регистр Y2 (573) с Load = ИЛИ-НЕ(CS, WR), выходы — на разъём Y.
6. Индикатор: регистр 573 → резисторы → FYS-5612 (ОК или ОА по группе).
7. Клавиатура: столбцы — 74HC173 (Cp ← WR, MR ← RST), кнопки с диодами, строки с подтяжкой и RC-фильтром → 74HC244 (OE = ИЛИ(CS, RD)), «И» строк → INT0.
8. Разъёмы питания, X, Y; фильтры **33 нФ на каждый корпус** + 470 мкФ на входе питания.

Сдать: «Фамилия ИО Схема-v1.png» (без потерь, не JPG) письмом «МПС-Схема» + черновик перечня (`perechen-km1.pdf`).

Проверка себя: ERC без ошибок (`erc-summary.txt` пуст), рамка — твои ФИО, группа, вариант; логика КМОП (74HC/AC, 1554).

## Шаг 5. Алгоритмы (самый важный шаг)

Программа тут — набор реакций на события, а не «сверху вниз».

1. **События:**

   | Событие | Кто | Что должно случиться |
   | --- | --- | --- |
   | Нажата кнопка | INT0 | узнать какая → цифра / «Тест» / «Сброс» |
   | Пришло число X2 | INT1 | двинуть «голову», флаги |
   | Кончился строб Y2 | Timer1 | поднять ножку строба в 1 |
   | Тик Timer0 | Timer0 | досчитать: погасить индикатор или закончить Y1 |
   | Ничего не происходит | — | главный цикл: есть данные и X1 ≠ 0 → выдать Y2 |
2. **Переменные**: X1, «голова», «хвост», 2 флага буфера, счётчик тиков, режим Timer0 (индикация или Y1), флаг «идёт строб Y2».
3. **Инициализация**: начальные значения всех переменных и ножек (стробы = 1, индикатор погашен, X1 = 0, буфер пуст, CS_EN = 1).
4. **Каждое событие** — шаги словами (готовые — в «Алгоритмах подпрограмм» ниже).
5. **Столкновения**: X2 пришло, пока главный цикл читает буфер → на время чтения запрети INT1; «Тест» во время индикации → индикатор гасим, Timer0 отдаём Y1.
6. **3–4 кода ошибок** для индикатора (заготовка ниже).
7. **Схемы алгоритмов** по ГОСТ 19.701 — текстом в `students/<ник>/pz/flow/*.flow`, рисует генератор (`docs/pz-guide.md`).

Проверка себя: «X1 = 3, пришло X2 = 10» → Y2 = (G + M + 13) mod 256 со стробом (у примера — 39).

   - Что будет при переполнении? (Старейший отсчёт затирается, «хвост» сдвигается, флаг переполнения = 1.)
   - Зачем RC-цепочка и диоды на клавиатуре? (Дребезг ≤ 5 мс; защита от КЗ при двух нажатых кнопках.)
   - Почему статическая индикация? (Регистр держит символ, МК не тратит время.)
   - Почему один таймер на Y1 и T3? (Задачи не пересекаются по времени.)

Общее для всех групп: клавиатура — INT0, строб X2 — INT1; T1 и T3 — Timer0, T2 — Timer1; клавиатура 4×3 при чётном M, 3×4 при нечётном;
X2 — до 4 отсчётов в секунду; фильтры 33 нФ на корпус + 470 мкФ. Таблица в машинном виде — `data/table-2026.yaml`.

## Производные параметры

- **Адреса:** окно устройства на выходе Yn — n·2000h … n·2000h + 1FFFh; в коде берём базовый адрес (`ADR_*` в `vars.inc`).
  Буфер — `BUF_START` … `BUF_START` + V − 1, `BUF_END` = `BUF_START` + V — точка заворота.
- **Указатели и флаги:** «голова» и «хвост» — по 2 байта, абсолютный адрес ячейки (младший байт по заданному адресу, старший — следующим),
  сразу грузятся в DPTR. Бит b лежит в байте 20h + b div 8, разряд b mod 8 (пример: бит 14 = 21h.6, бит 26 = 23h.2).
- **Стек:** SP = 07h, растёт вверх; до бит-области 20h — 24 байта. Банки регистров 1–3 (08h–1Fh) при SP = 07h заняты стеком — не переключай банк.
- **Таймеры** (12 МГц → 1 мкс): режим 1, TMOD = 11h. Строб Y2 — один отсчёт, загрузка 65536 − T2 (пример: 2332 → 0F6E4h).
  Y1 и T3 длиннее 65 мс — тик 1 мс (загрузка 0FC18h) и 16-битный счётчик тиков. Перезагрузка в обработчике теряет несколько мкс на тик —
  компенсируй (прибавляй к текущему TL0) или отметь в ПЗ2.

## Алгоритмы подпрограмм

Основа для схем алгоритмов и их пояснений. Обозначения: {KB}, {IND}, {Y2R}, {BUF} — адреса устройств (`ADR_KB`, `ADR_IND`, `ADR_Y2`, `BUF_START`).

### Инициализация (сразу после Reset)

1. SP = 07h (по ТЗ).
2. CS_EN = 1 (P3.4) — разрешить дешифратор адреса.
3. P1: стробы Y1 и Y2 в пассивной единице.
4. Переменные: X1 = 0; «голова» = «хвост» = {BUF}; флаг пустоты = 1, переполнения = 0; служебные флаги = 0.
5. Индикатор погасить: в {IND} код «выкл» (00h — общий катод, 0FFh — общий анод; `IND_OFF`).
6. Регистр Y2: записать 0 со стробом (пассивное состояние).
7. Клавиатура: 0 во все столбцы, чтобы любое нажатие опускало строку и вызывало INT0.
8. TMOD = 11h, таймеры остановлены.
9. Прерывания: IT0 = IT1 = 1 (по спаду); INT1 (X2) — высокий приоритет; разрешить EX0, EX1, ET0, ET1, EA.

### Главный цикл

1. Если X1 ≠ 0, буфер не пуст и строб Y2 не идёт → прочитать X2 из буфера → рассчитать и выдать Y2.
2. Иначе, если последнее выданное Y2 ≠ 0 и строб не идёт → выдать Y2 = 0 (один раз, со стробом); буфер не читаем.
3. Вернуться к п. 1. Остальное (клавиатура, запись в буфер, таймеры) — в прерываниях.

### Обработчик клавиатуры (INT0) — программа 1

1. Сохранить в стеке нужные регистры (ACC, PSW, DPL, DPH).
2. Для каждого столбца i: записать в {KB} маску с нулём только в бите i; прочитать {KB}; оставить биты строк (`anl A, #(1 SHL KB_ROWS) - 1`).
3. Замкнутых контактов ровно один → код клавиши из таблицы 3 ТЗ (movc) → A; ни одного или больше → A = 0FFh.
4. Записать 0 во все столбцы (режим ожидания INT0), сбросить IE0 (спады INT0 во время опроса — не новое нажатие).
5. Реакция на код (в полной программе): 0–9 → X1 = код, вывести цифру на T3; 10 «Тест» → погасить индикатор, запустить Y1; 11 «Сброс» → очистить буфер, погасить индикатор.
6. Восстановить регистры, reti.

### Запись в буфер (INT1) — программа 2 при нечётном M

1. Если буфер полон (флаг пустоты = 0 и «голова» = «хвост») → «хвост» + 1 с заворотом (старейший отсчёт теряется), флаг переполнения = 1.
2. DPTR ← «голова»; `movx @DPTR, A`.
3. «Голова» + 1; если = {BUF} + V → «голова» = {BUF}.
4. Флаг пустоты = 0.

В буфере помещается ровно V отсчётов: «голова» = «хвост» при флаге пустоты = 0 означает «полон».

### Чтение из буфера — программа 2 при чётном M

1. Запретить INT1 (критическая секция: обработчик тоже двигает указатели и флаги).
2. Флаг пустоты = 1 → «нет данных» (A = 0 или C = 1), разрешить INT1, выйти.
3. DPTR ← «хвост»; `movx A, @DPTR`.
4. «Хвост» + 1 с заворотом; флаг переполнения = 0 (после чтения буфер не полон).
5. «Хвост» = «голова» → флаг пустоты = 1.
6. Разрешить INT1, выйти. Результат — в A.

### Очистка буфера (клавиша «Сброс»)

Запретить INT1 → «хвост» = «голова» → пустота = 1, переполнение = 0 → разрешить INT1.

### Вывод на индикатор + T3 — программа 3 при M mod 3 = 0

1. Код ≤ 10 → код сегментов из таблицы (`movc A, @A+DPTR`); иначе «выкл». Для ошибки — добавить бит dp. Для общего анода — инверсия (`xrl A, #IND_OFF`).
2. Записать в {IND}.
3. Режим Timer0 = «индикация», счётчик = T3 / 1 мс, загрузить и запустить Timer0 (повторный вызов перезапускает отсчёт).
4. Обработчик Timer0: перезагрузка; счётчик − 1; дошёл до 0 → записать «выкл», остановить таймер.

### Строб Y1 — программа 3 при M mod 3 = 1

1. Строб уже идёт → выйти.
2. Погасить индикатор (Timer0 забираем у индикации).
3. P1.k = 0; режим Timer0 = «Y1», счётчик = T1 / 1 мс; запустить Timer0. Процедура сразу возвращается — не ждать в цикле.
4. Обработчик Timer0: перезагрузка; счётчик − 1; дошёл до 0 → P1.k = 1, остановить таймер.

### Расчёт и выдача Y2 — программа 3 при M mod 3 = 2

1. X1 = 0 → Y2 = 0; иначе A = X1 + X2 + (G + M) (8-битное сложение, перенос отбрасывается — это и есть mod 256; `Y2_CONST` = G + M).
2. Записать Y2 в {Y2R} (`movx`) — **до** начала строба.
3. P1.(k+1) = 0; флаг «идёт строб Y2» = 1; TH1:TL1 = 65536 − T2; сбросить TF1; запустить Timer1.
4. Обработчик Timer1: P1.(k+1) = 1, остановить Timer1, флаг = 0.

## Коды ошибок и ответы на п. 2.3

Таблицу ошибок ТЗ оставляет на твой выбор; заготовка (её же генератор кладёт в ПЗ2). Ошибка — цифра с горящей dp, висит до любого нажатия, но не дольше T3.

| Индикация | Смысл | Когда выставляется |
| --- | --- | --- |
| 1. | Нажато несколько клавиш | опрос нашёл больше одного замкнутого контакта |
| 2. | Нажатие не распознано | INT0 пришёл, а замкнутых контактов нет |
| 3. | Переполнение буфера | запись X2 затёрла непрочитанный отсчёт |
| 4. | Повторный «Тест» | «Тест» нажат, пока идёт строб Y1 |

**Минимальное время заполнения буфера (X1 = 0).** При X1 = 0 сигнал Y2 пассивен и буфер не читается, X2 приходит не чаще 4 отсчётов в секунду:
t\_min = V / f\_X2 = V / 4 с. Пример: V = 1744 → 436 с (7,3 мин).

**Максимальная глубина стека.** Худший случай — все уровни вложенности сработали одновременно: главный цикл в подпрограмме, её прервал
низкоприоритетный обработчик, а его — высокоприоритетный. Каждый call или вход в прерывание кладёт 2 байта, каждый push — 1:
D\_max = D\_main + (2 + P\_low + C\_low) + (2 + P\_high + C\_high). Должно быть D\_max ≤ 24 байта (от 08h до бит-области 20h).
Для программы 1 генератор ПЗ2 даёт замер в эмуляторе на всех сценариях проверки (у эталона — 4 байта: вход в INT0 + call процедуры).
